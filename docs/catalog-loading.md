# Catalog loading

Ordinary Songs searches use `GET /api/catalog/v1/{version}` plus the bearer-authenticated `/api/mobile/v1/catalog/overlay?version=...` for signed-in users. The complete public snapshot and account overlay are retained in memory, so subsequent text searches and sorts need no network request. iOS folder, series, level, and chart filters also run locally; Android retains its existing query/sort controls. The ordered chart selection chooses the corresponding one of 16 recommendation maps (`SD` and `DS` remain distinct). Favorites, recommendation, and recent ranked feeds keep their server endpoints.

Public snapshots use a separate typed disk cache per game version, conditional ETag requests, and shared in-flight downloads. Only validated schema-1 supported views with matching version, unique slugs, and `total == songs.count` enter this cache. It contains no account favorites or recommendations. Private overlays stay in memory, scoped to the account/authentication generation and version. Account or token changes discard them, including reauthentication as the same account. Explicit refresh fetches fresh catalog data; successful imports invalidate the local datasets and refresh chart hints. Favorite writes update the retained overlay, and writes completed during an older GET take precedence over that response.

Saved rows remain visible while refreshing; refresh errors offer retry. Warm retained datasets still support new searches while offline. After an app restart, existing account-scoped saved query results remain available, but a fresh authenticated overlay is required before new local queries can expose personal recommendations. A cold legacy server publishes its first page before fetching remaining pages. Only a missing snapshot/overlay endpoint (HTTP 404) permits that fallback. Failed, repeated, or capped page walks never become complete snapshots.

The query engines preserve the web's literal substring search, co-op token aliases, unusual-level bucket, AND/OR intersections, and Mongo binary sorting with null/unknown-series handling. They use published song identities, not rewritten selected-version slugs. A discovery-only “Because of You” alias matches the officially titled **Becouse of You** by **Srav3R & USAO**, without changing titles or matching unrelated artists.

On iOS, Home artwork reads the public cache immediately and revalidates it, preferring the selected game before filling missing titles from the other game. Android restores the public artwork index while loading the catalog. Shared image downloads and disk image caching are provided by the existing platform image loaders.

Validation: 96 iOS tests passed locally, including the shared 42-case web parity fixture, the shared title-alias fixture, all 16 ordered recommendation modes, no-network warm queries, account replacement, import invalidation, refresh failures, and favorite-versus-overlay races. Android has corresponding query/repository tests; its Gradle checks run in CI because this Mac has no Android SDK. Shared fixture changes trigger both platform workflows. No physical-device update is part of this change.
