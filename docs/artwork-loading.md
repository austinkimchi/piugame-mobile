# Artwork loading and scrolling

The iOS image loader keeps original public image responses in its existing URL cache, but prepares display-sized images on a worker actor. The decoded memory cache is keyed by URL and required square-crop pixels; a larger detail view does not reuse a small row thumbnail. Preparation honors image orientation and never enlarges a smaller source. Memory cost uses the decoded image's `bytesPerRow × height`, not compressed download size.

At 68 points and 3× scale, a 700×393 jacket becomes a 364×204 aspect-fill thumbnail, approximately 73% less decoded RGBA storage. This is a storage calculation, not a measured CPU or physical-phone scroll speedup. Source downloads remain shared by URL, preparation is shared by URL and size, and one disappearing view cannot cancel an image another row needs. Failed responses or corrupt cached bytes can be retried.

Songs speculates at most two nearby artwork requests at once, with a queue capped at 12 unique URLs. A moving viewport replaces pending work; changing the catalog or leaving the view clears that queue. Already active downloads finish and can be shared with visible rows. Visible requests start independently. Utility-priority prefetch tasks do not guarantee transport-level priority over every other request, and a jump to uncached rows can still show placeholders until the network responds. The app does not download the entire artwork catalog in advance.

Android uses Coil's ordinary `AsyncImage` in song/session rows, retaining target-size resolution, loading/error feedback, and decorative-image accessibility while avoiding per-cell subcomposition. No image-library upgrade is included.

Validation: 98 iOS tests passed on the existing iOS26.2 simulator, including 11 shared-cache tests and two bounded-prefetch tests. They cover separate image sizes sharing one download, raw-cache reuse, off-main preparation, decoded cost, cancellation, invalid images/retry, queue replacement, deduplication, and the concurrency cap. The signed-in iPhone17Pro simulator retained its account and displayed Home and catalog jackets during initial rapid-page checks. Extended cold-scroll and detail acceptance was left incomplete when the simulator view changed unexpectedly, to avoid interrupting possible user activity. Android device/frame-time measurements and physical-iPhone verification are not claimed; hosted Android CI checks compilation, unit tests, lint, and builds.
