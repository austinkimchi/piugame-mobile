# Artwork loading and scrolling

The iOS image loader keeps original public image responses in its existing URL cache, but prepares display-sized images on a worker actor. The decoded memory cache is keyed by URL and required square-crop pixels; a larger detail view does not reuse a small row thumbnail. Preparation honors image orientation and never enlarges a smaller source. Memory cost uses the decoded image's `bytesPerRow × height`, not compressed download size.

At 68 points and 3× scale, a 700×393 jacket becomes a 364×204 aspect-fill thumbnail, approximately 73% less decoded RGBA storage. This is a storage calculation, not a measured CPU or physical-phone scroll speedup. Source downloads remain shared by URL, preparation is shared by URL and size, and one disappearing view cannot cancel an image another row needs. Failed responses or corrupt cached bytes can be retried.

In-flight work tracks subscribers at both levels. When its last viewer disappears, a prepared-image task is cancelled; the underlying download stops only when no remaining image-size task needs it. Cancelled work does not publish a decoded image, and request IDs prevent a delayed old completion from clearing a replacement request after rapid re-entry. Already cached images remain reusable. This avoids keeping every passed-over row's download alive during a cold fling; it does not impose a global concurrency cap or promise a particular network latency.

Songs speculates at most two nearby artwork requests at once, with a queue capped at 12 unique URLs. A moving viewport replaces pending work; changing the catalog or leaving the view clears that queue. Already active downloads finish and can be shared with visible rows. Visible requests start independently. Utility-priority prefetch tasks do not guarantee transport-level priority over every other request, and a jump to uncached rows can still show placeholders until the network responds. The app does not download the entire artwork catalog in advance.

Android uses Coil's ordinary `AsyncImage` in song/session rows, retaining target-size resolution, loading/error feedback, and decorative-image accessibility while avoiding per-cell subcomposition. No image-library upgrade is included.

Initial qualification passed 98 iOS tests on the existing iOS26.2 simulator, including 11 shared-cache tests and two bounded-prefetch tests. The subscriber-cancellation follow-up adds cases for the last viewer leaving, different-size viewers sharing a request, delayed cancelled work completing after a replacement starts, and twelve obsolete rows cancelling their distinct downloads. Existing coverage also checks raw-cache reuse, off-main preparation, decoded cost, invalid images/retry, queue replacement, deduplication, and the prefetch concurrency cap.

The initial signed-in iPhone17Pro simulator check retained its account and displayed Home and catalog jackets during rapid paging. Extended cold-scroll and detail acceptance was left incomplete when the simulator view changed unexpectedly, to avoid interrupting possible user activity. The cancellation follow-up uses build-only local checks and hosted test execution; no new device or frame-time measurement is claimed. Android device/frame-time measurements and physical-iPhone verification are not claimed; hosted Android CI checks compilation, unit tests, lint, and builds.
